Introducción

Acerca del video analizado y su propósito

En este trabajo práctico analicé el video «Supabase, Tutorial Práctico y Overview (REST API)» del canal de tecnología Fazt Code.

El video es una guía práctica que enseña cómo dejar de perder días enteros configurando servidores tradicionales, base de datos y endpoints manuales. Explica cómo utilizar Supabase, una plataforma BaaS (Backend as a Service) de código abierto que monta automáticamente una base de datos PostgreSQL en la nube, autogenera una API REST completa y ofrece autenticación lista para conectar directo al frontend.

Conceptos Fundamentales

Los cinco pilares técnicos explicados de manera sencilla

☁️

BaaS (Backend as a Service)

Es como alquilar un backend completo ya programado y listo en la nube. Te da base de datos, seguridad y login para que vos como desarrollador solo te enfoques en el diseño y la interfaz del usuario.

⚡

Supabase

La alternativa de código abierto a Firebase. Te brinda un panel web para administrar datos en tiempo real, crear tablas interactivas y obtener endpoints listos para consumir sin codear el servidor.

🐘

PostgreSQL

Un motor de base de datos relacional potente, seguro y clásico. Guarda la información en tablas organizadas por filas y columnas, con tipado estricto (números, texto, booleanos, fechas).

🔌

REST API

El "puente" de comunicación entre tu sitio web y la base de datos. Permite pedir o mandar datos a través de peticiones HTTP estándares como GET, POST, PATCH y DELETE.

🔑

API Key / Anon Key

Una clave pública de identificación que se coloca en el código de tu sitio web para que Supabase sepa a qué proyecto pertenece la petición y qué permisos de lectura o escritura tiene permitido ejecutar.

Cuestionario Resuelto

Las 12 preguntas resueltas con claridad y lenguaje fluido

Pregunta 1

¿Cuál es el tema principal del video? Explica de qué trata.

El video trata sobre Supabase y muestra cómo funciona de forma práctica. Básicamente, explica cómo usar esta plataforma para crear un proyecto en la nube, armar tu base de datos y conectarla directo con tu página o app sin darte tantas vueltas ni perder tiempo en configuraciones complejas.

Pregunta 2

¿Qué problema o necesidad tecnológica se aborda?

Aborda el quilombo y el tiempo que lleva armar un backend desde cero. Normalmente tenés que configurar un servidor, instalar una base de datos y escribir un montón de código para poder guardar o leer datos. Supabase te resuelve todo eso rápido y sin complicarte la vida, entregando una solución "serveless" inmediata.

Pregunta 3

¿Cuáles son los cinco conceptos más importantes? Define cada uno.

  • BaaS (Backend as a Service): Es como alquilar el backend ya armado en la nube para que vos solo te preocupes por el diseño y el frontend.
  • Supabase: Es la herramienta de código abierto que hace de "backend preparado", bastante parecida a Firebase pero usando bases de datos tradicionales.
  • PostgreSQL: Es el motor de base de datos relacional (con tablas, filas y columnas) que usa Supabase por detrás.
  • REST API: Es el "puente" o caminito que conecta tu página web con la base de datos para pedir o guardar información mediante peticiones HTTP.
  • API Key / Anon Key: Es como una contraseña pública que le ponés a tu página para que Supabase sepa que la petición viene de tu proyecto.
Pregunta 4

¿Qué herramientas, programas o tecnologías se mencionan y para qué sirven?

  • Panel de Supabase: La página web oficial de Supabase donde creás los proyectos, administrás las tablas y configurás la seguridad.
  • PostgreSQL: La base de datos donde se almacenan y relacionan los datos reales.
  • VS Code y Rest Client / Postman: Programas o extensiones que se usan para probar si los datos están entrando y saliendo bien de la API antes de conectarla al código final.
  • JavaScript: El lenguaje de programación que usamos en el frontend para conectar la web con las claves y los endpoints de Supabase.
Pregunta 5

¿Qué procedimientos o pasos se explican? Preséntalos en orden.

  1. Crear una cuenta en Supabase y armar un proyecto nuevo.
  2. Crear una tabla en la interfaz (por ejemplo, una tabla de tareas o productos) y definir sus columnas y tipos de datos.
  3. Copiar la URL del proyecto y la API Key pública desde la configuración.
  4. Probar la conexión enviando datos desde un cliente de pruebas (como Rest Client o Postman).
  5. Hacer las operaciones básicas del CRUD: traer datos (GET), guardar nuevos (POST), actualizar (PUT/PATCH) y borrar (DELETE).
Pregunta 6

¿Qué ejemplos prácticos aparecen? Explica uno detalladamente.

Muestran cómo armar una lista de tareas (tasks) y una tabla de productos. En la web de Supabase creás la tabla con datos como el título de la tarea y si está terminada o no. Después, desde un programa de pruebas mandás un mensaje en formato JSON con la tarea nueva (por ejemplo, {"title": "Estudiar para el examen"}) y al toque se guarda sola en la base de datos sin que hayas tenido que escribir una sola línea de código en un servidor.

Pregunta 7

¿Qué conocimientos previos son necesarios para comprender lo explicado?

Con saber lo básico de HTML, CSS y JavaScript ya estás bien. También ayuda tener una idea general de cómo se organizan las tablas de datos (filas, columnas, tipos de datos) y saber qué es una petición web (como cuando abrís una página o enviás un formulario mediante HTTP).

Pregunta 8

¿Qué ventajas o beneficios ofrece la tecnología o procedimiento?

  • Te ahorra muchísimo tiempo de desarrollo al evitar configurar Node.js, Express o servidores manuales.
  • Es gratis para proyectos chicos, escolares y prototipos de prueba.
  • Es de código abierto, así que no te quedás "atrapado" con una sola empresa propietaria.
  • Automáticamente te crea la API REST y la documentación en cuanto creás cualquier tabla en el panel.
Pregunta 9

¿Qué dificultades, errores o precauciones deben considerarse?

  • Cuidado con las claves: La anon key se puede usar en la web del cliente, pero la clave service_role (que tiene superpoderes y se salta las reglas de seguridad) jamás debe ponerse en el código que ve el usuario.
  • Políticas de seguridad (RLS): Ojo con los permisos de Row Level Security; si los activás y no creás una regla que permita leer o insertar (por ejemplo para usuarios anónimos o autenticados), Supabase te bloqueará las peticiones por seguridad devolviendo un array vacío o un error de acceso denegado.
Pregunta 10

¿Cómo aplicaría lo aprendido en un proyecto informático real?

Lo aplicaría para hacer un sistema de inscripciones para el colegio, un gestor de préstamos de libros para la biblioteca o un registro de notas para el curso (2.º BTI). En vez de ponerme a programar un servidor largo en PHP o Node.js, crearía las tablas en Supabase y conectaría directo el formulario HTML de la web para guardar y consultar los datos al instante.

Pregunta 11

¿Qué parte del video consideras más importante y por qué?

La parte donde muestra cómo se genera la API automáticamente al crear una tabla en la base de datos. Me parece lo más clave porque ahí te das cuenta de todo el trabajo que te ahorrás al no tener que programar los endpoints a mano, entregándote además la documentación lista con ejemplos de código en JavaScript y cURL.

Pregunta 12

¿Qué conocimientos nuevos adquiriste y cómo los explicarías a otra persona?

Aprendí lo fácil que es conectar una base de datos a una página web hoy en día sin complicarse con servidores. Se lo explicaría a un compañero diciéndole: "Es como tener una planilla de Excel en internet que te da una contraseña y un link para que tu página web guarde y lea datos automáticamente sin pedirle permiso a nadie más".

Aplicación Práctica

Paso a paso para crear una tabla y consumirla desde JavaScript

01

Crear la Tabla

En el Table Editor de Supabase creamos la tabla products con columnas: id (int8), name (varchar) y created_at.

02

Configurar RLS

Habilitamos Row Level Security y creamos una regla básica ("Enable read access to everyone") para permitir que el frontend lea los datos.

03

Copiar Claves

En Settings > API copiamos la Project URL y la clave pública anon / public key para pegarlas en nuestro script.

04

Consumir vía Fetch

Llamamos al endpoint desde JavaScript usando fetch() enviando el header apikey para traer los datos en formato JSON.

app.js (Consumo de la API con JavaScript nativo) 
// 1. Definimos las credenciales de nuestro proyecto de Supabase
const SUPABASE_URL = "https://xyzcompany.supabase.co/rest/v1";
const ANON_KEY = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...";

// 2. Función para listar productos usando el endpoint automático
async function cargarProductos() {
  try {
    const response = await fetch(`${SUPABASE_URL}/products?select=*`, {
      method: "GET",
      headers: {
        "apikey": ANON_KEY,
        "Authorization": `Bearer ${ANON_KEY}`
      }
    });

    const productos = await response.json();
    console.log("Productos obtenidos con éxito:", productos);
  } catch (error) {
    console.error("Error al conectar con Supabase:", error);
  }
}

cargarProductos();

Conclusión Personal

Reflexión sobre el impacto de estas herramientas en nuestra formación

Conocer tecnologías como Supabase cambia por completo la perspectiva que tenemos como estudiantes del Bachillerato Técnico en Informática (BTI). Durante mucho tiempo se nos enseñó que para hacer andar una aplicación completa con base de datos era obligatorio montar servidores difíciles, lidiar con puertos, crear scripts en PHP o armar APIs línea por línea en Node.js.

Las plataformas BaaS no vienen a reemplazar el conocimiento técnico de fondo, sino a democratizar y acelerar el desarrollo. Para proyectos del colegio, ferias de ciencias o emprendimientos reales, nos permiten crear prototipos funcionales en un fin de semana. Como futuros programadores, dominar tanto las bases de datos relacionales como estas herramientas modernas en la nube nos da una ventaja enorme para adaptarnos al mercado profesional actual.
